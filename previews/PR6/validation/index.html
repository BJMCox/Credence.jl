Beliefs and validation

State what the expert means

BeliefMeaning
Hard(id, statistic, AtLeast(x))The statistic must be at least x.
Hard(id, statistic, AtMost(x))The statistic must be at most x.
Hard(id, statistic, Between(a, b))The statistic must lie in the closed interval [a, b].
Hard(id, statistic, EqualTo(x))The statistic must equal x exactly.
Approximate(id, statistic, target; scale, importance)A point target with an explicit discrepancy scale and optional importance.

Use Between to express an expert's tolerance. EqualTo supplies no implicit numerical tolerance. An approximate target records a discrepancy, not a pass/fail requirement.

Probability(a, b) means P(a < X <= b), including for discrete laws. Quantile(p) is the lower quantile, so it preserves atoms and support gaps. Mean() and Std() require those moments to exist. Statistic(f; label) supplies an analytic statistic of a measure, including properties of a joint prior.

Fit without hiding preferences

Each Candidate supplies a measure builder, parameter starts, and optional parameter bounds. Builders must return normalized MeasureBase measures. A failed start remains in the report with its error. Successful numerical fits retain the solver result and its return code.

Scalar optimization minimizes the sum of squared, scale-normalized target discrepancies, weighted by importance. Weights are divided by their maximum first. Multiplying all weights by a positive constant therefore leaves the objective unchanged. Zero-weight targets are not evaluated. Multiple targets require explicit importance weights for optimization.

Hard beliefs become constraints. Choose a solver that supports them, such as IPNewton() from OptimizationOptimJL. The default AD choice is Optimization.NoAD(); pass a supported AD type when the solver needs derivatives. The tutorials use deterministic solvers. Stochastic backends need their own explicitly configured RNG through their solver options.

compare(report) uses each approximate target's absolute, scale-normalized discrepancy. It retains Pareto dominance, ties, tradeoffs, and unresolved pairs. Importance weights do not collapse these comparisons into one score. Satisfying a hard requirement by a larger margin does not make a candidate preferable.

The returned fields identify retained results by (candidate_id, start_index):

FieldContents
feasibleIDs with all hard requirements satisfied and all targets defined.
dominatesOrdered (better, worse) result pairs by target discrepancy.
tiesPairs with equal discrepancy vectors.
incomparablePairs where improving one target worsens another.
unresolvedPairs whose evidence cannot support an exact comparison.

Evaluate() considers only supplied points. Optimization retains the solution from each start. Neither operation claims a complete feasible region or a complete Pareto frontier.

Check fixed candidates

validate(rng, report) evaluates the retained measures afresh. Analytic measure operations provide the default evidence. Failed or unavailable operations produce undefined checks.

For event probabilities, MonteCarlo(n; alpha) uses independent draws and Hoeffding bounds:

using Credence, MeasureBase, Randombelief = Hard(:lower_half, Probability(-Inf, 0), Between(0.4, 0.6))candidate = Candidate(:normal, _ -> StdNormal(), [0.0])report = fit(Xoshiro(10), Elicitation((belief,), (candidate,)))validation = validate(Xoshiro(11), report; plan=MonteCarlo(10_000; alpha=0.01))check = only(only(validation.checks))(; estimate=check.estimate, status=check.status)
(estimate = Estimate{Float64, Float64, Float64}(0.5015, 0.48522376369281267, 0.5177762363071873, :statistical), status = :satisfied)

The error budget is divided across all hard checks in this report. The bounds require a valid independent sampler. Monte Carlo validation currently supports Probability statistics. Repeated adaptive validation needs a separate error-budget policy. The caller owns the seeds.

An enclosure wholly inside a hard requirement satisfies it. A disjoint enclosure violates it. Overlap remains inconclusive. Evidence marked only :estimated cannot certify satisfaction or violation. Uncertain approximate-target comparisons remain unresolved.

Accept explicitly

select(report, id; validation, rationale) accepts a concrete result only when the validation belongs to that same report and every hard requirement is satisfied. Approximate targets stay targets, so review their achieved values yourself. Solver success does not replace validation.

Use role=:reference to retain a result for exploration without declaring acceptance. Selection records the role and rationale. measure(selection) returns the native measure without adding report metadata to the prior.
